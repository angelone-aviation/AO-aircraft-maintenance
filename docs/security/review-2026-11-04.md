# In-house security review, 2026-11-04

This is the second in-house review. The first was [2026-11-02](review-2026-11-02.md), made at commit `821d57d`. About 630 commits have landed since, including the refactor of the error, auth and command paths. Five reviewers worked in parallel, each in an isolated copy of the code: sign-in and accounts; tenant isolation; browser and delivery; CI and supply chain; disclosure and runbooks. Each one re-checked the earlier review's findings in their area.

**Rules for testing.** Every exploit attempt ran locally, in `convex-test` suites, vitest, or the demo production build served on a local port. Against https://ops.angeloneaviation.org the reviewers made only passive, read-only requests. Nothing touched the production Convex deployment.

## Verdict

**No Critical or High finding.**

**Fixed in this round, each with a test that fails without the fix:**

- A2: anonymous sign-in calls could grow the database without limit.
- A1: a look-alike email (the Unicode Kelvin sign) linked a Google or Microsoft identity to another user's account.
- T1: flight review leaked whether another program's flight exists.
- C9: an installed app showed itself instead of `security.txt`.
- P1: the auto-deploy condition was tightened.

**Added:**

- the disclosure policy (`SECURITY.md`, `/.well-known/security.txt`);
- [incident-response](../runbooks/incident-response.md) and [break-glass administrator](../runbooks/break-glass-admin.md) runbooks;
- CI security gates: a production dependency audit, and a gitleaks secret scan over the full history;
- a cross-program isolation regression suite (`convex/tenantIsolation.test.ts`).

**Tenant isolation is sound.** There are 92 public functions: 89 in the app, against 82 at the last review, plus 3 from the auth library. Every one requires a session except the documented `identities.providers`. Each takes the Flight Program from server-side membership.

A probe called 50 of them against Flight Program A's records and files as two users: B's administrator, and a user who is B's administrator and also a read-only member of A. Every call was refused or returned nothing of A's, and no row or file of A changed.

The largest open item is a design decision, **A3**: the first Google or Microsoft link to an account trusts whoever the provider says owns the email. It only matters once single sign-on is switched on.

## Checked and sound

- **Sign-up and password reset are closed** on the server for every flow. Single sign-on never creates a user, and links only to the one active user with a provider-verified email. After the first link it matches by the provider's subject.
- **Microsoft "nOAuth"** is closed: the plain email claim is never trusted, and the token's issuer must match its own tenant.
- **One-time sign-in codes** only work in the browser that started the sign-in. Redirects only go back to `SITE_URL`.
- **Administration:** no privilege-escalation path. The last active system administrator can't be disabled or demoted. Bootstrap and migration functions are internal.
- **Tenant isolation:**
  - every program-scoped function derives the program on the server;
  - client ids are checked against their program before any write;
  - `writeChanged` never overwrites a row it didn't load;
  - the owner portal is still a whitelist.
- **Uploads:** an allowlist of types and sizes, no SVG or HTML; `deleteBlobIfUnused` checks every referencing table.
- **Outbound calls** go to fixed `https` hosts, with redirects refused and timeouts set. Credentials are sealed with AES-256-GCM, tied to their row.
- **Browser:**
  - no HTML injection points in `src/`;
  - user links go through `safeHref`;
  - CSV export neutralizes formulas, and the Excel workbook writes strings, never formulas;
  - print labels are escaped and sandboxed;
  - no source maps or secrets ship;
  - demo mode can't be switched on in a production build.
- **Bug-hunt repro scripts:** 26 of 27 report NOT REPRODUCED. The 27th is stale after the login redesign; an updated copy also reports NOT REPRODUCED.

## Addendum 2026-11-10

- **A second anonymous function, by design.** `pushSubscriptions.publicKey` (added 2026-11-09 with ADR-0012) answers without a session. It returns the deployment's VAPID public key, which is public by design: every browser that subscribes to alerts receives it, and it lets no one send a message (that needs the private key, which never leaves the Convex environment). An anonymous caller learns only whether push is configured. It is listed beside `identities.providers` in CONTEXT.md and in `NOT_PROGRAM_SCOPED` in `convex/tenantIsolation.test.ts`.
- **Push endpoints are now limited to the browsers' push services** (`PUSH_SERVICE_HOSTS`), checked when a device subscribes and before every send, so "outbound calls go to fixed https hosts" holds again; before, any member could name any https URL as their device's endpoint.
