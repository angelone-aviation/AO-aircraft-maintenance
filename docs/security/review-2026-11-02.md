# In-house security review, 2026-11-02

Decided with the user on 2026-11-02: the pre-launch review is done in-house, now, with no external penetration test at this stage. Four reviewers read the code in parallel, one per area. Each finding below was traced in the code. Findings marked **verified** were also re-checked by hand, or reproduced by a test. Nothing was tested against a live deployment.

## Verdict

**One critical issue blocks launch.** The installed `@convex-dev/auth` 0.0.95 lets anyone on the internet delete any record by its ID through the public `auth:signIn` action, with no sign-in (advisory GHSA-579h-4cfp-fh53). A regression test reproduces it on 0.0.95, and 0.0.96 fixes it. The fix is on the local branch `security/upgrade-convex-auth`. **Any deployment still running 0.0.95 is exposed today.** That includes the current production deployment if it was built from this code.

Apart from that, tenant isolation, credential encryption, outbound requests, email escaping, CSV export, file-type checks and the service worker are sound. The remaining findings are Medium or lower.

## Checked and sound

- **Tenant isolation**: every one of the 82 public Convex functions requires an active session. Program-scoped ones go through `checkContext`, which takes the active program from server-side memberships. Client-supplied ids are checked against the owning program. No cross-tenant read or write was found.
- **Sign-up and reset are closed server-side.** Bootstrap and migration functions are internal. No privilege escalation path was found. Passwords are 12–128 characters, hashed with scrypt.
- **Owner portal** is a whitelist: no flights, change log or attachments.
- **Change-log actor and time** are always set by the server. No public function deletes change-log rows.
- **Credential encryption** uses AES-256-GCM with random IVs and fails closed without the key. Credentials never reach the client, logs, the change log or error messages.
- **Outbound requests** go to fixed hosts with redirects refused and timeouts set. The one provider-supplied URL is host- and path-pinned.
- **Email digest** escapes every user string. CSV export neutralises formula cells. No HTML-injection sinks exist in `src/`. Print labels are escaped and rendered in a sandboxed iframe.
- **Uploads** use a server-side type allowlist with no SVG or HTML, and size limits. Files are served from the Convex origin.
- **Demo mode** cannot be switched on in a production build. The service worker caches static assets only. No source maps ship. No secrets are in the repo or the legacy PHP folder.
