# Aircraft Spruce connection

Under **Settings → Flight Program → Aircraft Spruce account** (Vendors links there), choose **Link Aircraft Spruce account**. Enter the API user ID, password and API key, and confirm the account catalog currency. The app validates the credentials against the documented orders download endpoint before saving them. Inventory administrators manage the connection for their active Flight Program. Each program has its own account and catalog; there is no global fallback.

Credentials are stored in a dedicated server table, not in vendor notes, user snapshots, offline storage, or audit details. Settings queries return only connection status, version, currency and catalog refresh metadata. Replacing/disconnecting an account invalidates previous catalog and order snapshots. Linking and disconnecting are recorded in the change log with the actor, never the credentials. Requests that finish after replacement cannot save results against the new account. Configure credentials in the connected app, not demo mode; local research credentials are not imported automatically.

Choose **Refresh Aircraft Spruce catalog** to download the current catalog. Refresh is manual until supplier rate limits are confirmed. Each Flight Program can make 5 account checks (link or replace), 4 catalog refreshes and 30 order syncs per hour. An invalid or empty catalog leaves the previous one intact. Search loads the server-stored catalog and returns up to 30 matching products; narrow the search if needed. Catalog search is explicit, not performed on every keystroke. The initial implementation reads the catalog file for each search; a future indexed importer can improve search latency.

In a parts request or draft PO, choose **Find at Aircraft Spruce**. Verify that the product matches your internal part and that one supplier order unit equals one inventory/order unit. Automatic pack/unit conversion is not supported. Supplier part number and unit are stored separately on the line and carried from requests into POs. Existing internal part numbers/descriptions are preserved; empty fields are populated. A blank vendor is filled with Aircraft Spruce; review any existing vendor or per-line overrides. Mapping is retained on the saved document, not in a global reusable part directory.

A valid net price is copied only when the configured catalog currency matches the document currency. Missing/invalid prices or a currency mismatch leave the existing price unchanged for manual review. Catalog refresh never rewrites existing document prices. Supplier availability and due text remain separate from local inventory; blank availability means unknown. PDF purchase orders include the supplier part number and order unit.

Place the order manually with Aircraft Spruce and provide your internal PO number. On the saved PO, open **Aircraft Spruce order progress** and select **Sync Aircraft Spruce order**. The app requests an export filtered by PO number, then retains exact matches. Alternatively enter an exact Aircraft Spruce order number to link it manually. Confirm that the supplier order belongs to this PO before using the manual link. Multiple orders with the exact PO reference are shown together. A failed or empty sync retains the previous snapshot and its timestamp.

The panel displays supplier order references, status, invoice references, parts, ordered/shipped/backordered quantities and carrier/tracking details. Repeated syncs replace the previous snapshot. They never append local shipments or receipts. Export row identity and cumulative-versus-shipment quantity semantics remain unverified, so this release shows supplier data for review rather than summing it or automatically recording quantity movements. Use the existing **Record shipment** and **Receive parts** controls for verified movements. Receiving remains the only operation that increases inventory and reserves request-linked receipts.

Cart creation, checkout and automatic order placement are not implemented because their API contracts are unavailable. No real orders are created by linking, refreshing, searching, or syncing. The verified endpoints are `/api/download/products` and `/api/download/orders`; see [API review](aircraft-spruce-api-review.md).

Deployment requires both the updated Convex schema/functions and frontend. This feature adds the `spruceAccounts` and `spruceOrders` tables and server actions; it does not configure accounts or deploy itself.
