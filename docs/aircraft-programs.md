# Aircraft and Flight Programs

The Aircraft page supports adding and editing aircraft using the legacy PHP aircraft fields: registration, make, model, serial number, current Hobbs and tach readings, cycles, landings, and operational status. Serial number is optional. Program ownership is assigned automatically from the active Flight Program. Registration must be unique. System and Flight Program administrators create aircraft; users with maintenance permission may edit their assigned aircraft. Changes require an online connection and are automatically recorded in audit history.

Select **Total time source** (Hobbs or tach) and enter **Total time adjustment** in hours. The calculation is:

`Aircraft total time = selected meter reading + Total time adjustment`

Readings and adjustments accept tenths of an hour. Adjustments may be positive or negative; the resulting total time cannot be negative. The form shows the resulting total live. Switching the selected meter automatically recalculates the adjustment to preserve the displayed total; the adjustment remains editable.

Inspection and installed-component hour tracking use aircraft total time. Hobbs and tach remain separate raw readings for flight entry and pilot verification. Changing aircraft counters records a dated counter event, preserving the original flight baselines and meter selection for historical flight review. The event records which counters the administrator changed and what they read before. Backdated flights crossing a counter change require review. When a review recalculates totals, a counter event overrides only the counters it changed: accepted corrections, accepted backdated flights and rejections before it still reach the other totals. A review is refused as an inconsistent chronology when it would change a reading a counter change was based on, for example an earlier flight's Hobbs after the Hobbs was set to a new meter's reading, or the reading of the time source when the source or total time adjustment changed. Record such a correction as a new counter change instead. Every flight whose starting readings a review recalculates gets its own change-history entry. Installed-component baselines move with aircraft counter corrections so the correction itself does not add or remove accumulated component time or cycles. Changes that conflict with existing maintenance baselines are rejected. Calendar month and year deadlines continue to fall at the end of the target month.

The Flight Programs page provides a separate directory with program name, address, email, contact name, and website. System administrators create programs; Flight Program administrators can edit their active program. Aircraft reference a program by its stable identifier, so renaming a program updates its displayed name on linked aircraft. See [Flight Program access](flight-program-access.md) for user memberships, program switching, transfers, and offline behavior. Program names are unique, and website addresses automatically receive `https://` when entered without a protocol. Existing HTTP or HTTPS prefixes are preserved.

Verification covers permissions, stale edits, duplicate request retries, program assignments and renames, meter switching, counter chronology, installed-component accumulation, and browser add/edit flows. No legacy import is required.
