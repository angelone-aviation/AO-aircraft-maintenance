# Aircraft checklists

Open **Checklists** in the navigation. Use **Import .fmd** to select a ForeFlight checklist, review its name, aircraft assignment and contents, then **Save checklist**. Imports create a new set; they do not overwrite the original file or an existing set. **New checklist** creates a blank set with Normal, Abnormal and Emergency categories.

The reader has category tabs, a group/checklist sidebar, challenge/response rows and preserved headings and notes. Tap an item or use **Check next item**. **Skip next item** leaves an item explicitly incomplete. Reset applies to the current checklist or the whole set after confirmation. Progress counts only checkable entries, never headings or notes. Checkmarks and skips are saved per user, browser and checklist revision and work offline after the app has been cached. They are not a shared flight log or a sign-off. Editing/importing the shared definition requires a connection. A saved revision starts fresh personal progress.

**Edit checklist** supports metadata and aircraft assignment; adding, renaming, deleting and reordering groups and checklists; and adding, editing, deleting and reordering check items and headings/notes. Click an entry to expand its editing fields. All edits remain a draft until Save; cancellation asks before discarding changes. Conflicting saves are rejected without replacing the newer record.

**Export .fmd** downloads the current saved definition. It excludes personal checkmarks. The source document's wording, case, whitespace, object IDs, notes and extension fields survive import/export. Additional source actions are retained but are not executed by this app. Unsupported item types, schema versions, malformed encryption, duplicate IDs and oversized files are rejected rather than partially imported. File limit: 2 MiB encrypted; the validated document must fit the 750,000-byte storage limit and contain at most 10,000 entries.

Definitions are stored in Convex for connected users and IndexedDB in demo mode, scoped to the current Flight Program and optionally one aircraft. Aircraft checklist editing requires flight or maintenance permission for that aircraft. Program-wide library definitions require program-admin permission to edit. Read access follows the selected aircraft/program scope. Version checks, authorization and validation run on the server, not just in the UI.

## Format references and verification

The format was verified against the [EFIS Editor format implementation](https://github.com/rdamazio/efis-editor/tree/main/src/model/formats) and its [ForeFlight schema](https://github.com/rdamazio/efis-editor/blob/main/src/model/proto/foreflight.proto). FMD contains a 16-byte IV followed by AES-128-CBC encrypted UTF-8 JSON with container type `checklist` and schema version `1.0`. The format uses a publicly documented fixed interoperability key; it does not provide private document encryption. The implementation uses native Web Crypto, available on HTTPS and localhost, without an external parsing service.

Reader interactions are based on the [ForeFlight Checklist guide](https://support.foreflight.com/hc/en-us/articles/115005692847-ForeFlight-Checklist-Guide). This app does not implement ForeFlight's speech feature or synchronize with ForeFlight.

The supplied `N377YB complete Check List.fmd` imports as 12 checklists, 598 entries, 401 checkable items and 197 comment/heading entries. Domain tests compare every decoded source field against a separately decrypted source and verify an export/import round trip. Browser tests exercise import, offline checking/skipping, reload persistence, reset, editing, export equality, mobile layout and malformed-file handling. Backend tests cover persistence, permissions, conflicts and auditing.

## Guided flight trial

On Checklists, enable **Guided flight trial**. Select an aircraft, one of its unlogged flight plans, and a checklist assigned to that aircraft or the Flight Program library. Use Edit checklist to change its aircraft assignment. Choose the preflight and shutdown sections, then start. Each flight starts with fresh checkmarks and a frozen copy of the checklist revision.

In the preflight section, compare the last recorded Hobbs/tach (and cyclic meter where applicable) against the aircraft and explicitly confirm. The most recent accepted flight's shutdown fuel and starting oil readings are shown as a reference, not automatically treated as current levels. Record fuel and each engine's oil starting levels **before additions**, plus quantities added (enter zero if none). At shutdown, enter actual ending meters and fuel level. Review flight log opens the existing flight form for actual date, pilot, route, cycles, landings and readings before Save flight.

Fuel consumption is starting level + additions − shutdown level. Missing readings stay unknown. Fuel supports US gallons, litres, pounds or kilograms; oil supports US quarts or litres. Units are explicit and changing a unit does not convert existing numbers. Twin-engine oil is recorded separately. The flight log shows all three fuel values, consumption, and fuel consumption per actual primary-meter hour for accepted flights with a positive duration. Oil is recorded only at preflight: starting level before additions, and quantity added. Measured oil use since the previous start is the previous starting level + previous additions − current starting level, shown on the later flight. It requires adjacent accepted flights for that aircraft with matching engine and units and complete readings; missing data, review entries, range readings, or a negative result leave consumption unknown. Legacy shutdown oil values are retained in saved records but are not used in this calculation. No values are inferred from planned duration.

Draft readings and progress are saved in this browser, separately for each user, Flight Program and backend. They can be resumed after navigation/reload, including offline with a previously cached workspace. Drafts do not sync between devices. Export draft provides a JSON backup; there is no draft-import screen yet. Unsaved edits in the final review are discarded when that dialog closes, while readings entered in the checklist remain in the draft. Saving uses the existing offline queue; inspect Flight log or Sync center for acceptance, review or sync errors. Aircraft updates since preflight trigger the existing conflict review flow. Checklist revision and recorded progress are retained with the flight; corrections preserve that provenance.

To undo the workflow trial, uncheck **Enable guided flight trial**. The normal checklist and flight-log screens remain available. Turning it off retains unfinished drafts and saved flights. Discard draft deletes only the unfinished local run; it does not roll back saved flights. The optional fuel/oil fields and recorded flight history remain available even with the trial off.

Oil also supports **Range only (no units)**. Starting levels use a dropdown: Add, 25% above Add, 50% above Add, 75% above Add, and Full. These describe the span between dipstick marks, not the percentage of total oil capacity. Quantity added remains a numeric amount with its own US qt/L selector. Range readings are saved and shown in flight history but do not produce consumption or per-hour rates. Switching between measured and range modes clears that engine's readings so numeric quantities cannot be mistaken for positions on the dipstick.

Use **Engine start section (optional)** to place engine-start duration (seconds) and maximum EGT (°C) fields after the last checklist item in that section. A matching start section is suggested when available; the selection can also be changed in an existing guided draft. Fields are optional, use separate left/right entries for twins, survive draft reloads, and populate the final flight-log review. Select “Do not include engine start fields” to hide the panel; any readings already entered remain in the draft and review.

When adding oil, select **Use inventory for engine oil**, then the inventory location, oil part number and **Stock units used**. Twin engines can choose separate sources or share a stock item. Stock units are whole items (for example, bottles); oil volume added remains a separate measurement, because stock lots do not define bottle capacity. The same controls are available in the regular flight form and final guided-flight review.

Saving/syncing the flight issues the selected stock exactly once in the same server transaction as the flight record. Both engines' requests are combined when using the same lot. Insufficient stock, an oil lot past its expiration date (refused exactly as **Issue stock** refuses it) or an invalid/cross-program source rejects the whole submission; an offline entry stays in Sync center for resolution/retry and does not reserve stock. Pilots with flight permission may issue oil from their aircraft's Flight Program, but only stock an administrator has marked **Engine oil** on the inventory item; any other stock item is refused by the server and the offline demo, and the part-number list shows only oil items, listing an expired lot as expired without offering it. General inventory editing permissions are unchanged. The stock version increments and `stock.oil_used` audit entries link the movement to the flight. Those entries record only the stock item id and its quantity before and after, never cost, vendor, invoice, PO or location. Change-log entries about stock, location and vendor records are shown only to program administrators, even when they carry an aircraft tag, so older entries that copied the full stock record stay private without rewriting them. After deploying the oil marker, run `npx convex run management:backfillOilMarker` once: it marks as oil every stock item already used through `stock.oil_used` and records a `stock.oil_marker_backfill` entry (actor `system`) for each item it changes. Items never used that way stay unmarked until an administrator marks them. Flight history displays the chosen part, location and stock quantity.

Oil is physically used even when a flight needs meter review. Consequently, held flights deduct stock, and rejecting a flight does not return that oil. Posted inventory links and quantities cannot be changed through flight review. Use an inventory adjustment to correct stock mistakes, with its normal audit explanation. Old flight records without inventory selections remain valid and cause no retroactive deduction.
