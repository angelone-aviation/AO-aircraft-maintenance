# Records package

**Export records package** gives a mechanic or administrator the complete record set Angel One holds for one aircraft, as one ZIP file, for an FAA inspector (14 CFR 91.417(c)), a buyer at transfer of the aircraft (91.419) or an insurer. It is the on-demand per-aircraft export that [ADR-0004](adr/0004-logbook-generator-and-status-record-system.md) decided on. The button is in the aircraft dialog on the Dashboard (**View aircraft**, beside **Export status sheet**) and on the **Change history** screen once an aircraft is chosen in the filter. It works in demo mode.

## Who can export

Users with **maintenance** permission on the aircraft, Flight Program administrators and system administrators. Aircraft owners keep the status sheet PDF only: the package holds flights, work detail and the change log, which the owner portal leaves out. The server scopes what each user's workspace holds, so a package never contains more than its exporter could see on screen. The package is assembled in the browser from those records, so the export itself refuses anyone else ("Records packages are for users with maintenance permission on the aircraft."); the server does not stop a pilot reading the same records on screen, so this rule keeps the package to the people who hand it over rather than keeping its contents secret.

## What the package holds

The file is named `<registration>-records-<YYYY-MM-DD>.zip` and contains:

- `README.txt`: the aircraft, the Flight Program, when the package was generated and by whom, a **WARNINGS** block when a table is incomplete, what each file is, and any files left out with the reason.
- `records.pdf`: every table below, printed in the same style as the status sheet, in DejaVu Sans so any character prints. Wide tables are landscape; the Form 337 list is portrait. The footer of every page says that the signed logbook entries remain the maintenance record.
- One CSV per table (UTF-8 with a byte-order mark, every cell quoted; a dash on paper is an empty cell in the CSV): the six status sheet tables (`status-overview.csv`, `status-components.csv`, `status-inspections.csv`, `status-airworthiness.csv`, `status-form-337.csv`, `status-discrepancies.csv`), then `flights.csv`, `discrepancies.csv`, `work-orders.csv`, `ad-compliance.csv`, `components.csv`, `component-requirements.csv`, `form-337.csv` and `change-log.csv`.
- `form-337/`: every Form 337 copy on the aircraft record, named `<upload date>-<file name>` (the upload date in UTC); archived copies are under `form-337/archived/`. A second upload of the same name on the same day gets ` (2)`.
- `files/`: the attachments of the aircraft's work orders, named the same way.
- `logbook-photos/`: the current [logbook page photos](logbook-photos.md) on the aircraft record (a flight's line or a work order's signed page), named the same way; `README.txt` lists each one with the flight or work order it shows. Archived photos are left out.

Every time in the package is UTC and its column heading says so ("Reported (UTC)", "When (UTC)"), and the dates in file names are UTC too, so a row's file name and its upload time agree on the day. A date without a time, such as a work order's dates or a deferral, is the calendar date as recorded. The README says the same.

The tables:

## Size guard

A package copies at most **150 MB** of stored files. Files are taken in order (Form 337 copies, then work-order attachments, then logbook page photos, oldest upload first); one that would exceed the limit is skipped and smaller later ones may still be taken. A file that cannot be downloaded is skipped too. Skipped files are listed in `README.txt` with the reason and counted in the message under the button, so the exporter can fetch them separately from the record. The tables are never cut.

## What the package is not

Angel One generates unsigned logbook entries and is the system of record for the six 91.417(a)(2) status records; it is not the signed maintenance record ([ADR-0004](adr/0004-logbook-generator-and-status-record-system.md)). The signed pages in the aircraft's logbooks remain the legal record, and the package says so in its README and on every page of `records.pdf`. Values are as recorded when the package was generated; corrections are appended in Angel One with a reason, so the change log shows every change.
