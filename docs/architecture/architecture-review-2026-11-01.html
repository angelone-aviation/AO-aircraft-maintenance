Problem. The applier is deep and tested; the adapter around it is shallow and copied: each mutation re-derives hydrate, diff, persist, audit replay and idempotency, and unloaded collections default to [], so a rule cannot tell “empty” from “not loaded”.

Solution. One module whose interface is the needs list and the applier; the demo already has this module as modify() in store.ts.

  • locality: table mapping, audit stamping, idempotency in one file
  • leverage: new command = applier + one needs list
  • tests: one convex-test for the transaction; 18 glue tests retire
  • “not loaded” becomes explicit (see G)

Deletion test: delete the glue and it reappears in 18 callers. It is earning its keep; it has just never been given an interface.

G. Make “not loaded” visible in the Snapshot interface

Worth exploring · design note for A

src/domain/model.ts Snapshot · every applier

After: applier declares what it reads
saveWorkOrder(s: Pick<Snapshot, "workOrders" | "taskCards" | …>, cmd)

Problem. A rule that reads an unloaded collection silently sees “empty”. This is the correctness risk the current shape hides.

Solution. A's needs list makes it explicit at runtime; Pick<Snapshot, …> makes it explicit at compile time.

F. Narrow the Backend interface

Speculative · leave

src/data/backend.ts (~90 methods, ~40 of identical shape)

Two adapters make this a real seam, and the width is honest: distinct operations with distinct types. Collapsing to execute(kind, payload) trades compile-time typing for fewer lines. Revisit only once D's command table exists; then the methods can be derived rather than removed.

Top recommendation

A, with B folded in

It concentrates the server write path in one module, fixes the un-stamped audit rows, makes “which collections does this command need” explicit, and replaces 18 glue tests with one transaction test. C comes next: flight submission is the most safety-relevant write and the only one whose two implementations have already drifted. D's move is mechanical and rides along with either.

Already deep, do not touch: authorization (programContext.ts + access.ts), the domain appliers and their 66 test suites, the Workspace/outbox, App.tsx.
