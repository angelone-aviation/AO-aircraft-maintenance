# Credentials and keys

Every credential Angel One depends on: what it unlocks, where it lives, where Aaron keeps it, and what to do when it is lost or leaked. Names only: the repository is public, so no value ever goes on this page.

- **A credential** is anything that lets its holder in, or act as Angel One: an account login and its recovery codes, a deploy key, an API token, a password, a signing key, or a secret URL.
- **The rule:** keep each one in the password manager, or only in the one place it is used. Never in chat, email, an issue, a file or the repository.
- **Who holds them:** Aaron. A sealed paper copy of the Convex login and the break-glass account is kept for when he cannot act ([break-glass](../../runbooks/break-glass-admin.md#the-break-glass-credentials)).
- **Shown once:** many keys are displayed only when made, and GitHub secrets cannot be read back. A lost one is re-created, not recovered: that is fine, as long as the few that cannot be re-created are in the password manager ([checklist](#your-password-manager-should-hold)).

- **GitHub `production` secret** / **`backups` secret:** GitHub → the repository → Settings → Environments → `production` (or `backups`) → Environment secrets.

## Your password manager should hold

The ones that cannot be re-created, or that unlock the rest. Keys marked "None: GitHub only" or "None: Convex only" above stay out of it: if one is lost, make a new one.

- [ ] `CREDENTIALS_ENCRYPTION_KEY`, and any `CREDENTIALS_ENCRYPTION_KEYS`. The one value nothing can replace.
- [ ] Convex login and recovery codes (shown once). Also in the sealed paper copy.
- [ ] GitHub login and 2FA recovery codes (shown once).
- [ ] Cloudflare login and recovery codes (shown once).
- [ ] Better Stack, Resend, Geoapify, FAA DRS and domain registrar logins, with any recovery codes.
- [ ] The FAA DRS API key and its expiry date, 2027-10-14.
- [ ] Each Flight Program's Aircraft Spruce login, or who holds it.
- [ ] Your own administrator password in the app.
- [ ] The break-glass administrator. Also in its sealed paper copy.
- [ ] The `accounts@angeloneonline.org` mailbox login.
- [ ] Only if backup encryption is turned on: the `age` private key, plus the organization's sealed copy.

## If a credential leaks

1. **Revoke it at its source** (the "If leaked" column). A deploy key, the sign-in key, the R2 token or the Cloudflare login is SEV1: start at once.
2. **Replace it where it lives** (GitHub secret, Convex variable or Settings), update the password manager, and run Deploy or the Nightly backup by hand where the row says so.
3. **Find out what it was used for** in the provider's audit or access log, and follow [incident response](../../runbooks/incident-response.md#leaked-secret) for the timeline and who to tell.

## Rotation

When each one is rotated or reviewed is in [Checklists](checklists.md): access review [quarterly](checklists.md#quarterly), break-glass [twice a year](checklists.md#twice-a-year), tokens and the credentials check [yearly](checklists.md#yearly), the FAA key and one-off clean-ups under [one-off and dated](checklists.md#one-off-and-dated). Everything else is replaced on a leak, or when someone who saw it leaves.
