# Reference library

Upload a PDF from **Aircraft → Manuals → Upload manual**, or the **Reference library** navigation entry. Enter the document title, number, revision/temporary revisions and optional revision date. The aircraft association controls access using existing Flight Program and aircraft permissions. The library lists all manuals the user can read in the active program.

PDFs up to 200 MiB are supported, including the supplied 98.48 MiB Cessna 441 manual. The browser checks that the PDF opens and records its page count. Connected workspaces upload directly to Convex file storage through an authenticated upload ticket; file bytes are not sent through mutation arguments or cached snapshots. The browser declares the file's SHA-256 when it asks for the ticket; completion rechecks permission and claims only a blob uploaded during the ticket's hour with exactly those bytes, size and PDF type that no other record uses. A rejected file is never deleted at completion. An hourly job removes tickets a day after issue, together with the blobs uploaded for them that no record refers to. Each user can start 20 manual uploads per hour. Demo mode saves the PDF as a Blob in a separate IndexedDB database. Demo files are local to that browser, not shared uploads.

Each upload is a separate, immutable manual record. Upload a new revision as a new record; old references continue to identify the previous revision. This first version does not provide file deletion or replacement, automated revision comparison, manual deduplication, or automatic activation of extracted maintenance records. The assisted search workflow below proposes records for review.

Inspection forms, component service requirement forms, and task cards include a reference-library selector, section, printed-page label and PDF page number. These are structured references to the saved manual UUID, not temporary storage URLs. Page numbers are validated against the manual page count. For the Cessna Phase 2 example use section `5-12-02`, printed page `1`, PDF page `79`.

A reference opens the application's manual viewer, which resolves the stored document after checking current aircraft access and opens the PDF at the selected page. The native browser PDF viewer supports reading, searching and downloading. Some browsers do not honor PDF page fragments; the page number is shown above the viewer and an external-open/download option is provided. No automatic mapping of arbitrary section names to pages is implemented; an extraction workflow can populate the same reference fields later.

Linked task cards inherit a source inspection or component requirement's manual reference when created using the linked-card flow. Task-card edits continue to use the existing version, signoff invalidation and closed-record rules. Reusable task templates and automatic work-order task generation remain separate future work; manual search creates reviewed schedules and service requirements.

Manuals follow the uploading aircraft's access when that aircraft transfers programs. A reference to a manual outside current access remains stored and displays an unavailable message; it does not bypass aircraft permissions. Connected manual files open online unless they are [kept on this device](#keep-on-this-device); demo files persist locally. Failed uploads may leave unreferenced storage objects/upload tickets; automated orphan cleanup is not included yet.

Validation covers upload authorization, ownership and one-time ticket completion, metadata mismatch rejection, library/read scoping, reference page bounds and persisted task references. Browser coverage uploads from an aircraft, reloads the library, saves an inspection reference and reopens it after reload; when the supplied Cessna file exists, it uses the real 2,937-page PDF and page 79.

## Keep on this device

Select **Keep on this device** on a manual in the Reference library, or in the manual viewer, to download it once for use without a connection. The library row shows the manual's size, then the download progress with **Cancel download**, then **On this device**. A kept manual opens from the device first, instantly and offline, from the library, the viewer and every inspection, component requirement and task-card reference; **Find maintenance items** also reads the kept copy instead of downloading the manual again. The viewer says when it opened the device copy. If the copy is missing or cannot be read, the manual opens online as before, which needs a connection. **Remove from this device** deletes the copy. Keeping a manual needs a connection and uses the same authorized, five-minute file link as opening one ([file links](file-links.md)). Opened online, the viewer downloads the manual once, so **Open PDF in browser** and **Download PDF** keep working however long it stays open.

The library shows how many manuals are kept on the device and the space they use and, where the browser reports it, the space left for the app. Keeping a manual asks the browser to protect the app's storage from automatic clean-up (persistent storage); the library shows whether it is protected.

Kept copies are stored in the browser's Cache Storage, separately for each deployment and each user, keyed by the manual's UUID rather than a temporary file URL. Manuals are immutable records, so a kept copy never needs refreshing; a new revision is a separate manual to keep. A copy is only opened for a manual in the signed-in user's current snapshot that their aircraft and Flight Program permissions allow, and it is removed:

- when the user signs out, or the session ends on the server;
- when the snapshot no longer allows the manual: access revoked, aircraft transferred to another program, or another Flight Program selected;
- for any other user of the same deployment on the device;
- on request, with **Remove from this device**.

Limits: browser storage quotas apply and vary by browser and free disk space; a manual larger than the space left is refused with a message, and nothing is kept from a canceled, failed or incomplete download. Without persistent storage the browser may remove kept manuals when the device runs low on storage, and Safari may clear a website's storage after some days without use unless the app is added to the Home Screen; an evicted manual opens online again until it is kept once more. Private browsing windows may not keep files, or clear them when closed. The PDF viewer files are cached when a manual is kept; after an app update, open the app once online so they are cached again for offline use. Demo uploads are already saved in the browser and open offline without keeping them; Keep on this device works in the demo as it does in a connected workspace, and signing out of the demo removes its kept copies.

Unit tests cover keeping, reading back, removal, per-user and per-deployment isolation, quota and download failures, cancellation and purging; browser coverage keeps a manual, opens it offline from the library and from an inspection reference, removes it and checks that sign-out removes it.

## Find maintenance items

On a saved manual, select **Find maintenance items** in the library or manual viewer. Confirm **Edit model association**: an aircraft model defaults to the uploading aircraft’s make/model; a component manual needs its manufacturer, model and optional part number. This association filters targets; access still follows the original aircraft and Flight Program. Existing components have a new optional **Component model** field in their details. Model/manufacturer matching ignores case and extra whitespace, but does not infer model aliases or serial applicability.

Choose the first and last PDF page, then **Search manual**. Start with the inspection/time-limits chapter for large documents. Progress and cancellation are available, and canceled/failed searches label their results as partial. Filter the results by a phrase such as “Phase 2” or “oxygen”. The two tables show inspection/service candidates and suggested trackable components/limits, with suggested hours, cycles and calendar months, extracted text and a link to the manual revision/page. Large result sets display 100 rows per table initially; use **Show more suggestions** or filter.

Select **Create inspection** to expand a form in the table. Choose an accessible aircraft of the associated model, review/correct the name, description, intervals, ATA chapter and source reference, and enter verified compliance history. The form previews recurring due limits. One-time limits can be entered separately. Saving uses the existing inspection validations, permissions and audited save path. Missing compliance history is not filled from current aircraft readings.

Select **Create component service requirement** to choose an existing component and complete the existing requirement form inline. For an aircraft manual, targets are components associated with matching aircraft; for a component manual, targets match the component model, optional manufacturer and optional part number, including accessible inventory components. Review life-limit/overhaul/inspection type, absolute-versus-relative limits, TSN/TSO/TSR basis and calendar rules. Due values preview when the form has sufficient valid data. Enable relevant tracking dimensions on the component before importing a suggested limit. Repeat imports of the same search item into the same aircraft or component are rejected on the server and in demo mode; this does not identify semantically equivalent items at different source pages or manual revisions.

In the component suggestions table, **Create component** opens identity, tracking, location and installation/opening-history fields. Enter verified usage (zero only when verified), model/part/serial and actual location. After saving the physical component, the service-requirement form appears for that component. These are two explicit saves: closing before the second save leaves the component saved without the proposed requirement. Existing matching components are shown to help avoid adding the same physical unit twice. The component and resulting requirement both retain the manual page reference.

Search runs locally in the browser over selectable PDF text using conservative text patterns, not an AI or OCR service. It recognizes phase cover descriptions and numbered/line-based maintenance entries, but cannot establish that it found every inspection or interpret arbitrary table layouts, footnotes, continuation pages, program alternatives or external publications. Complex/multiple/initial/age-based limit expressions are flagged and left without prefilled intervals. Always read the source and confirm applicability and the supported schedule before saving. Phase descriptions retain their source page; full multi-page task-card/checklist generation is not included. Inspection descriptions allow 2,000 characters and service notes 10,000; longer extracts remain available in the open search results and original PDF.

No active records are created by searching. Unsaved search results last for the open window; closing it requires another search. Saved inspections, components, requirements, model associations and source links persist in the shared backend (or browser demo). No existing uploaded manual or maintenance record needs a data migration.

## CSV alternative

Use **Import maintenance CSV** on a manual to download inspection, component and task templates plus AI extraction instructions. CSVs load into a validated review table and use the existing record forms; they do not activate records automatically. See [maintenance CSV import](maintenance-csv-import.md) for the file relationships, supported fields, source references, duplicate handling and initial-versus-recurring workflow.
