# Maintenance CSV import

Open **Reference library → Import maintenance CSV** on the source manual (also available in its viewer). Download the three header templates and **AI instructions**. The instructions include the selected manual’s identity/revision, exact columns, supported values, extraction rules and original-PDF page-number requirements. Give these instructions and a chapter/page range to the AI. Import its UTF-8 CSV output using **Validate and preview CSVs**.

This workflow replaces the need to rely on the app’s text-pattern search for extraction. It does not invoke an AI service or send files to an external provider. The existing PDF search remains available separately.

## Three related files

| File              | One row represents                                                                                              | Action after review                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inspections.csv` | An inspection package with description, first thresholds, recurring intervals, conditions and source            | Select the associated aircraft model’s actual aircraft, enter compliance history, save an inspection                                                     |
| `components.csv`  | A suggested component and one service/life-limit requirement, with model/part identity and explicit limit bases | Create a physical component with verified identity/baselines, then save its requirement; or select a matching existing component and add the requirement |
| `tasks.csv`       | One checklist task, with its manual item code, instruction, applicability and parent ID                         | Select a saved parent and create one linked task template with its instruction in the description                                                        |

Each row has its own stable `id`, unique within that file. Use the same IDs on subsequent exports of the same manual revision. `parent_type` in tasks is `inspection` or `component_requirement`; `parent_id` matches an inspection or component row’s `id`. No database UUIDs, aircraft registrations or compliance history need to be generated by the AI.

Load one, two or three files together. A task-only file can reference parents previously saved by this CSV importer from the same manual. A task whose parent is neither in the submitted files nor already saved is an error. A parent present in the CSV must still be saved before its task can be created. Component tasks currently require an installed component because task cards belong to an aircraft.

## Review and save

Loading files writes no maintenance records. Any structural error blocks the entire preview and identifies the file, record and field where possible. Correct the CSV and load it again. A new preview replaces the old unsaved preview. Unsaved candidates last only while the import window is open.

The manual’s model association filters eligible targets. Aircraft-manual component rows also restrict existing targets using nonblank imported model, manufacturer and part number. Component identity, applicability, operating program, serial restrictions and the exact schedule still need human verification.

Initial hours/cycles are not merged into recurring limits. When present, the inspection form requires an explicit choice: create an initial one-time schedule or create the recurring schedule after initial compliance. Both can be saved separately and have distinct duplicate identities; task-parent selection labels the initial record. Completing the initial schedule does not automatically activate a recurring schedule.

The component form preserves imported life-limit/overhaul/inspection type, TSN/TSO/TSR basis, absolute/relative modes and day/month/year calendar units. Imported numeric limits are suggestions; existing validations require appropriate tracking and actual compliance history. Component creation and requirement creation are two separate saves, so closing after the first leaves the physical component saved without its requirement.

Tasks are saved as draft task cards, with empty execution results and no signatures. Each source task is a separate card, not a multi-task checklist template. Add measurement requirements, acceptance limits, resources or additional signoff settings in Task cards before use.

Duplicate CSV imports are rejected per source manual, stable row ID and destination: inspection/initial schedule per aircraft, requirement per component, task per saved parent. These checks run in both the shared backend and demo. They do not detect equivalent entries with new IDs, different source manuals or records entered manually. Reimporting is not an update operation: edit saved records in their normal screens. Multiple physical units can legitimately share a component definition, so creating physical components is not deduplicated by definition ID.

## Format rules

The app’s templates are the authoritative column lists. Header order may vary, but every listed header is required and unknown/duplicate headers are rejected. Unused values are blank. Use comma-delimited UTF-8, conventional CSV quoting for commas/newlines, and doubled embedded quotes. Each file is limited to 2 MiB and 2,000 records. Preview tables show 100 rows initially, with filter and “Show more” controls.

Positive hours allow one decimal place. Cycles/calendar values are positive integers; all numeric inputs are capped at 1,000,000. Do not include units, thousands separators, formulas, zero placeholders or `N/A` in numeric columns. Unknown limits remain blank. `pdf_page` is mandatory, one-based, within the uploaded manual, and refers to the original PDF rather than a chapter-only extract. Section and printed page can be blank if genuinely unknown.

Preserve conditions and external references. Unsupported conditional/age/event/sequence rules should leave their affected numeric fields blank and explain the rule in `conditions`. The importer validates structure and existing record constraints; it cannot verify that an AI interpreted the manual correctly. Existing calendar month/year due calculations use the end of the due month and must not be assumed suitable for every age-based limit.

Descriptions and conditions are validated against storage limits rather than silently truncated: inspection summary plus conditions ≤2,000 characters, component description plus conditions ≤10,000, task instructions ≤9,000 and task applicability ≤1,000. The downloaded AI instructions spell out the individual field limits and allowed enum values.

## Save reusable templates

Each inspection/component candidate now also offers **Save as template**. It opens a model-grouped, interval-only form, requires no last-complied values and includes linked checklist tasks from the loaded batch. See [Inspection templates](inspection-templates.md). This action saves a reusable definition rather than an aircraft schedule or installed component requirement.

## One destination for a whole task file

Use **Import task file to one template or inspection** to upload task rows without per-row parent assignment. It accepts the sample `Item code,Task,Zone,Manual reference,PDF page` format and the existing tasks.csv format. The chosen destination applies to every row. See [Task CSV import](task-csv-import.md).

## Delete reusable inspection templates

In Inspection templates, choose **Delete templates**, select the rows to remove (or Select all visible, up to 100), then **Review deletion**. The confirmation names the selected templates and lists associated reusable task cards. Confirm to delete the templates, embedded task definitions, associated reusable cards, and those cards' attachments. The operation is atomic and recorded in audit history.

Association uses the explicit `template:<UUID>:initial` or `template:<UUID>:recurring` source keys created when a template is activated, plus reusable cards linked to those schedules or component requirements. It does not guess by name or match unrelated CSV IDs. Existing schedules and component requirements remain, as do independent work-order job cards and their history. Other cards' prerequisite references must be resolved before deletion. Maintenance permission is required for the Flight Program and every aircraft affected by the cascade. If any selected template or associated card changes after the preview, reopen the preview before deleting.
